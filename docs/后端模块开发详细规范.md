# SpeedInspect 后端模块开发详细规范

## 🎯 总览
本文档详细描述每个后端模块的开发细节、完成标准、功能要求和性能指标，作为开发和验收的依据。所有模块开发必须严格遵循此规范，确保代码质量、性能和可维护性。

---

## 📋 通用开发规范（所有模块必须遵循）
### 代码规范
1. **Python版本**：Python 3.12+，使用uv作为包管理器
2. **类型安全**：所有函数、方法必须添加类型注解，mypy检查必须100%通过
3. **代码格式**：使用ruff作为linter和formatter，遵循PEP8规范
4. **注释要求**：
   - 公共API必须有docstring，包含参数、返回值、异常说明
   - 复杂业务逻辑必须添加注释说明设计思路
   - 变更历史需要在注释中记录
5. **错误处理**：
   - 所有异常必须使用自定义异常体系，禁止直接抛出HTTPException
   - 错误码统一规范：2xxxx参数错误、3xxxx权限错误、4xxxx业务错误、5xxxx系统错误
   - 所有错误必须记录日志，包含request_id便于排查

### 接口规范
1. **RESTful设计**：URL使用名词复数，HTTP方法对应CRUD操作
   - GET /api/v1/users - 获取用户列表
   - POST /api/v1/users - 创建用户
   - GET /api/v1/users/{id} - 获取单个用户
   - PUT /api/v1/users/{id} - 更新用户
   - DELETE /api/v1/users/{id} - 删除用户
2. **统一返回格式**：
   ```json
   {
     "code": 0,
     "message": "success",
     "data": {},
     "request_id": "xxx",
     "timestamp": 1234567890
   }
   ```
3. **分页规范**：所有列表接口必须支持分页，默认page_size=20，最大page_size=100
   ```json
   {
     "code": 0,
     "message": "success",
     "data": {
       "items": [],
       "total": 100,
       "page": 1,
       "page_size": 20,
       "has_next": true
     },
     "request_id": "xxx"
   }
   ```

### 性能要求
1. **普通接口**：响应时间P95 < 200ms，QPS ≥ 1000
2. **计算密集型接口**：响应时间P95 < 2s，QPS ≥ 100
3. **IO密集型接口**：响应时间P95 < 500ms，QPS ≥ 500
4. **数据库查询**：单表查询≤10ms，多表关联查询≤50ms，禁止N+1查询

### 安全要求
1. **鉴权**：所有非公开接口必须携带JWT Token，权限校验必须通过依赖注入实现
2. **参数校验**：所有输入参数必须通过Pydantic校验，禁止直接使用用户输入
3. **数据加密**：敏感数据（密码、手机号等）必须加密存储，禁止明文
4. **接口限流**：所有接口必须配置限流规则，防止恶意刷接口
5. **日志脱敏**：日志中禁止打印敏感信息（密码、Token、手机号等）

#### 模块定位

| 用户登录 | 支持验证码登录、密码登录、第三方登录 | 登录响应时间<100ms，支持分布式会话 |
| 用户信息管理 | 用户信息修改、头像上传、实名认证 | 信息更新实时生效，头像存储在对象存储 |
| 权限管理 | RBAC权限体系，支持多角色（普通用户/管理员/企业用户） | 权限校验响应时间<10ms，权限变更实时生效 |
| JWT认证 | Token生成、校验、刷新、吊销 | Token有效期：Access Token 30分钟，Refresh Token 7天 |
