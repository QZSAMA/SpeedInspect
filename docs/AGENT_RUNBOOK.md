# Agent 开发与维护手册

本手册供后续 Agent 在缺少历史对话时恢复上下文。强制规则见根 [AGENTS.md](../AGENTS.md)。

## 启动检查

1. 执行 `git status --short --branch`，保护所有已有改动。
2. 执行 `git fetch origin --prune`，确认 `dev`、远端默认分支和基线 SHA。
3. 阅读 `PROJECT_STATUS.md`、`技术方案.md`、`ROADMAP.md`、`DEVELOPMENT.md`、最近 CHANGELOG 和相关 ADR（当前为 `docs/adr/0001-vercel-unified-runtime.md`）。
4. 把任务写成：目标、范围、非目标、验收标准、风险、依赖、回滚方式。
5. 运行受影响区域的基线检查；若已有失败，记录原始输出，避免误归因。

## 实现纪律

- 一次任务只解决一个可独立审查的目标。并行 Agent 使用隔离分支/worktree，避免同一文件。
- Bug 修复先写回归并确认失败原因；实现后运行局部和综合检查。
- API、数据库、Blob、AI 和 UI 分边界实现。每个写操作有身份、归属、schema、幂等和错误路径。
- 设计或现实发生变化时同步状态、方案、ADR、API/数据文档和 CHANGELOG。
- 不把 mock、TODO、随机值或计划文档当作完成证据。报告实际命令、退出码和未验证环境。

## 故障处置

### Vercel 构建失败

复现相同 Node/npm 和 Root Directory，先运行 `npm ci`、typecheck、lint、build。核对环境变量是否仅在运行期可用、客户端是否误引用服务端模块、包体和动态导入。修复后用同一提交重新生成 Preview。

### 数据库或迁移失败

暂停写流量/发布；记录 migration ID 和错误，不直接修改生产表。先在恢复副本验证 forward fix 或回滚。迁移和应用版本必须兼容滚动阶段。恢复后验证所有者隔离与数据数量。

### Blob 上传/读取失败

核对会话、inspection owner、token 过期、MIME/字节限制和对象状态。禁止临时公开 bucket 或绕过授权。孤儿对象通过可重试清理任务处理。

### AI 超时、429、错误输出

把任务保存为可重试或失败状态，保留稳定错误码和 requestId；遵循最多尝试次数与费用上限。schema 不合法时不生成报告，不用 mock 替代。必要时关闭新任务入口，已有证据保持可访问。

### 权限或数据泄露事件

立即停止相关路径，保全最少必要日志，轮换受影响凭据，评估对象/用户/时间范围并修复授权根因。使用两个账号写回归。对外通知和生产数据操作需要用户授权。


只有代码、测试、文档、变更记录和交接一致时才算完成。生产部署、付费服务、破坏性迁移和数据删除需要用户明确授权。
