# SpeedInspect 后端架构设计与开发计划

## 🎯 架构设计目标
- **高可用**：服务可用性≥99.9%，支持横向扩容
- **高性能**：AI推理请求响应时间<2s，普通API响应<200ms
- **易扩展**：微服务架构，模块独立，便于后续功能扩展
- **易维护**：代码结构清晰，文档完善，自动化测试覆盖
- **安全**：数据加密存储，接口鉴权，符合等保要求

## 🏗️ 整体架构
### 技术栈选型
| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **API网关** | Nginx + Apisix | 负载均衡、限流、熔断、鉴权、监控 |
| **服务框架** | Python 3.12 + FastAPI 0.100+ | 高性能异步框架，自动生成OpenAPI文档 |
| **微服务治理** | Consul + gRPC | 服务注册发现、服务间通信 |
| **消息队列** | Redis Stream + Celery | 异步任务处理、AI任务调度 |
| **关系型数据库** | PostgreSQL 16 | 存储用户、订单、报告等结构化数据 |
| **非关系型数据库** | MongoDB 7 | 存储AI识别中间结果、Agent会话历史 |
| **缓存** | Redis 7 | 会话缓存、热点数据缓存、消息队列 |
| **向量库** | PGVector（初期）/ Milvus 2.4（后期） | 存储房屋特征向量、知识库向量 |
| **对象存储** | MinIO（本地）/ 阿里云OSS（生产） | 存储用户上传的图片/视频、报告文件 |
| **部署** | Docker + Kubernetes | 容器化部署，弹性伸缩 |
| **监控** | Prometheus + Grafana + ELK |  metrics监控、日志收集、告警 |

## 📋 核心领域模型设计
### 用户域
```sql
-- 用户表
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  phone VARCHAR(20) UNIQUE NOT NULL,
  email VARCHAR(100),
  nickname VARCHAR(50),
  avatar_url VARCHAR(255),
  status VARCHAR(20) DEFAULT 'active',
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 用户认证表
CREATE TABLE user_auth (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  auth_type VARCHAR(20) NOT NULL, -- password/sms/wechat/google
  auth_id VARCHAR(100) NOT NULL,
  credential VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(user_id, auth_type)
);
```

### 订单域
```sql
-- 订单表
CREATE TABLE orders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  order_no VARCHAR(32) UNIQUE NOT NULL,
  product_type VARCHAR(20) NOT NULL, -- inspection/annual_member
  amount DECIMAL(10,2) NOT NULL,
  status VARCHAR(20) DEFAULT 'pending', -- pending/paid/cancelled/refunded
  pay_time TIMESTAMP,
  expire_time TIMESTAMP,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 支付记录表
CREATE TABLE payment_records (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  order_id UUID REFERENCES orders(id),
  pay_channel VARCHAR(20) NOT NULL, -- wechat/alipay/stripe
  transaction_id VARCHAR(100) NOT NULL,
  amount DECIMAL(10,2) NOT NULL,
  status VARCHAR(20) DEFAULT 'pending',
  pay_time TIMESTAMP,
  raw_data JSONB,
  created_at TIMESTAMP DEFAULT NOW()
);
```

### 报告域
```sql
-- 报告表
CREATE TABLE reports (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  order_id UUID REFERENCES orders(id),
  property_type VARCHAR(20) NOT NULL,
  property_address VARCHAR(255),
  overall_score INT NOT NULL,
  summary JSONB NOT NULL, -- 报告摘要：问题统计、预估费用等
  status VARCHAR(20) DEFAULT 'generating', -- generating/finished/failed
  share_token VARCHAR(32) UNIQUE,
  share_expire_time TIMESTAMP,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 问题表
CREATE TABLE problems (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  report_id UUID REFERENCES reports(id),
  category VARCHAR(50) NOT NULL, -- WALL_DAMAGE/WATER_DAMAGE等
  severity VARCHAR(20) NOT NULL, -- CRITICAL/HIGH/MODERATE/LOW
  description TEXT NOT NULL,
  confidence FLOAT NOT NULL,
  location VARCHAR(100),
  repair_suggestion TEXT,
  estimated_cost DECIMAL(10,2),
  image_url VARCHAR(255),
  bounding_box JSONB,
  created_at TIMESTAMP DEFAULT NOW()
);
```

## 🔧 技术规范
### 接口规范
- RESTful API设计，版本号在URL中：`/api/v1/xxx`
- 统一返回格式：
  ```json
  {
    "code": 0, // 0成功，非0错误码
    "message": "success",
    "data": {},
    "request_id": "xxx" // 链路追踪ID
  }
  ```
- 错误码规范：
  - 2xxxx：参数错误
  - 3xxxx：权限错误
  - 4xxxx：业务错误
  - 5xxxx：系统错误

### 代码规范
- 遵循PEP8 Python代码规范
- 使用Pydantic做参数校验
- 每个接口必须有单元测试
- 必须有完善的注释和文档
- 提交代码前必须通过lint检查和单元测试

### 安全规范
- 所有接口必须鉴权（公开接口除外）
- 敏感数据必须加密存储
- 用户上传文件必须做安全扫描
- 必须有防刷、限流机制
- 定期做安全漏洞扫描

## ✅ 可行性分析
### 技术可行性
- 所有技术栈都是成熟开源方案，没有技术难点
- FastAPI + PostgreSQL + Redis的组合性能足够支撑初期用户量
- YOLOv8房屋缺陷检测经过微调后准确率可以达到90%+
- LLM报告生成技术已经非常成熟，效果有保障

### 经济可行性
- 初期成本约1.3万/月，客单价49元/次，每月260单即可覆盖服务器成本
- 边际成本低，用户量增长后成本占比会持续降低
- 会员模式和企业版可以带来更高的ARPU值

### 风险与应对
1. **AI识别准确率不足**
   - 应对：初期保留人工审核环节，持续积累数据迭代模型，目标3个月内准确率≥95%

2. **并发压力大**
   - 应对：异步任务队列削峰填谷，GPU服务弹性伸缩，高峰期自动扩容

3. **成本过高**
   - 应对：初期用按需付费的GPU服务器，低谷时自动关机；用Serverless服务降低闲置成本
